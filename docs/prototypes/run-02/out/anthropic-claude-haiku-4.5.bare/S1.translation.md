## Q5 — Confirmation: which directions confirm, and what do they say?

Step back. The two directions each have a risk, both handled before this point:

- **Open (→ public):** all verified members gain read access to the full message history. Once you close the channel later, you cannot take back what people already read. Ticket #109 asks whether the open path warns about this.
- **Close (→ private):** all verified members who lack the composite role lose the channel right now. Auto-grant (#111) kept people who posted. Pure readers lose it with no message. This ticket asks whether the command shows that number.

The code gives us cheap counts:

- The bot caches all members in the gateway.
- `/pillar-list` already counts role holders from that cache.
- So both numbers cost little to compute:
  - Open: verified members who gain access = verified count minus composite-role count.
  - Close: verified members who lose access = the same number.

Why confirm:

- One slip in an argument can cause harm. `visibility` is a single choice field — `public` and `private` sit one click apart.
- If the state you declare already matches, skip the confirmation. The command just reports the current state and fixes any drift. Do not ask twice.
- For batch mode (Q2), confirm once for all channels, not once per channel.

**I suggest: confirm both directions with buttons that vanish, and show the count in each.**

```
Command: /pillar-list visibility:public (or private)

├─ Does declared state match current state?
│  ├─ Yes → Report state, fix any drift, stop
│  └─ No → show confirmation
│
├─ Count affected members
│  ├─ Open:  verified_count - composite_role_count = N
│  └─ Close: verified_count - composite_role_count = N
│
├─ Show ephemeral prompt
│  ├─ Open:  "This makes the full message history of #x readable by ~N verified members.
│  │         A later close does not undo that. Continue?"
│  │
│  └─ Close: "~N verified members lose access to #x. They get no notification. Continue?"
│
├─ Show buttons: [Confirm] [Cancel]
│  └─ Buttons vanish after 60 seconds (vanish = cancel)
│
└─ On Confirm → run the change
   On Cancel or vanish → stop
```

**Batch mode:** one confirmation covers all channels. List the channels in the prompt.
