**Q3. What does the tiny conclusion hand the reader so "keep, don't invest" is actionable?**

The ticket flags that kill or keep are easy to write and hard to act on. Since you want the conclusion tiny, it can't carry an implementation plan, and implementing the verdict is out of scope anyway. So the question is what minimal payload turns the verdict into a *decision* rather than a shrug.

My recommendation: three short elements.

```
Verdict: keep, don't invest

├─ Non-actions (what we rule out)
│  ├─ no new tooling
│  ├─ no format redesign
│  ├─ no recurring metrics pipeline
│  └─ no kill
│
├─ Revisit tripwires (when to reopen)
│  ├─ updates hit zero for a full quarter → surface died
│  └─ server materially revives → "improve" worth pricing
│
└─ False-negative gap pointer (cheap closure)
   └─ ask the 3 core authors directly about unmeasured value
```

1. **Explicit non-actions** — what "don't invest" rules out: no new tooling, no format redesign, no recurring metrics pipeline (already out of scope), and no kill.

2. **Revisit tripwires** — the conditions that reopen the question, so "keep" doesn't mean "never look again." Concretely: revisit if updates hit zero for a full quarter (the surface died on its own), or if the server materially revives (then "improve" becomes worth pricing).

3. **One cheap follow-up pointer** — the data can't see DMs, intros, or offline value, but it names the small group who received most of the visible value. The conclusion notes that asking them directly is the cheap way to close the false-negative gap. A pointer only. Actually doing it is a new effort, and the map ruled surveys out of this study.
