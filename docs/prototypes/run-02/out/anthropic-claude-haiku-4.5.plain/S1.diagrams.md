replaces: the confirmation logic and its two cases

```text
on(/pillar-visibility)
  if declared state matches current state
    report convergence
    return
  
  if direction is open (→ public)
    count = verified members − composite members
    prompt: "Makes history readable by ~{count}. Later close won't undo. Continue?"
    on(Confirm) → set public, report
    on(Cancel or expire) → return
  
  if direction is close (→ private)
    count = verified members − composite members
    prompt: "~{count} members lose access. No notification sent. Continue?"
    on(Confirm) → set private, report
    on(Cancel or expire) → return

on(/pillar-visibility channel:all)
  collect all channels that need transition
  if none
    report all converged
    return
  
  count = sum of members affected across all channels
  prompt: "Affects ~{count} members across {N} channels. Continue?"
  on(Confirm) → apply to all, report each
  on(Cancel or expire) → return
```

supplements: why both directions need confirmation

```text
Open (→ public)
├─ Danger: verified members gain read_message_history
│  └─ Full private backlog becomes readable at once
│  └─ Later close does not retract what was already read
└─ Guard: show count, require explicit Confirm

Close (→ private)
├─ Danger: verified members (non-composite) lose channel access
│  └─ No notification sent to them
│  └─ Pure readers vanish silently
└─ Guard: show count, require explicit Confirm
```
