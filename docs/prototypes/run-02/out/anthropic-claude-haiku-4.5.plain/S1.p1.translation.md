**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions have different dangers, both already decided upstream:

- **Open (→ public):** all verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while it was open. #109 asked whether the open path warns about this.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected the people who posted. Pure readers lose it with no signal. The ticket asks if the command shows that number.

The bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are free:

- Open: verified members who gain access = verified count minus composite-role count.
- Close: members who lose access = the same number, for the same reason.

Why confirmation matters:

- A confirmation step stops an argument slip. `visibility` is one choice field on one command — `public` and `private` sit one click apart.
- The idempotent case must not ask. If the declared state already matches, there is no transition, so there is nothing to confirm. The command just converges and reports.
- The "all channels" form (Q2) must confirm once for the batch, not once per channel.

My recommendation: **confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

Confirmation logic and its two cases:

```text
on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state
    report converged, repair any drift
    return
  
  if visibility:public
    count = verified members − composite members
    prompt "History readable by ~{count}. Later close won't undo. Continue?"
    on Confirm → open channel, report
    on Cancel or expire(60s) → return
  
  if visibility:private
    count = verified members − composite members
    prompt "~{count} members lose access, no notification. Continue?"
    on Confirm → close channel, report
    on Cancel or expire(60s) → return

on(/pillar-visibility channel:all visibility:public|private)
  collect all pillar channels needing transition
  if none
    report all converged
    return
  
  count = (verified − composite) × channels needing transition
  prompt "{count} total access changes across {N} channels. Continue?"
  on Confirm → apply all, report per-channel
  on Cancel or expire(60s) → return
```

The buttons expire after 60 seconds. Expiry means cancel.
