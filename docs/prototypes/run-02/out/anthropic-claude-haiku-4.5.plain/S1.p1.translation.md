**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions have different dangers, both already decided upstream:

- **Open (→ public):** all verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while it was open. Ticket #109 asked if the open path warns about this.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected the people who posted. Pure readers lose it with no signal. The ticket asks if the command names that number.

The bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are cheap:

- Open: verified count minus composite-role count = how many gain access.
- Close: the same number = how many lose access.

A confirmation step protects against a slip. `visibility` is one choice field on one command — `public` and `private` sit one click apart.

The idempotent case must not nag. If the declared state already matches, there is no transition, so there is nothing to confirm. The command converges and reports.

The "all channels" form (Q2) must confirm once for the batch, not once per channel.

**My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- No confirmation when the declared state already matches — the command only reports, and repairs drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- The buttons expire after 60 seconds. Expiry means cancel.

```text
on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state
    report convergence
    return
  
  if visibility:public
    count = verified members without composite role
    prompt: "Makes history readable by ~{count}. A later close does not undo. Continue?"
    on(Confirm)
      grant read_message_history
      report open
    on(Cancel or 60s timeout)
      report cancelled
  
  if visibility:private
    count = verified members without composite role
    prompt: "~{count} members lose access. No notification sent. Continue?"
    on(Confirm)
      revoke read_message_history
      report close
    on(Cancel or 60s timeout)
      report cancelled

on(/pillar-visibility channel:all visibility:public|private)
  collect all pillar channels with drift or state mismatch
  count = verified members without composite role
  prompt: "Affects {count} members across {N} channels. Continue?"
  on(Confirm)
    apply visibility to each channel
    report batch result
  on(Cancel or 60s timeout)
    report cancelled
```
