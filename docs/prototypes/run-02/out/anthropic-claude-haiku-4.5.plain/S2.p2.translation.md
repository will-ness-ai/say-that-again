Your checkout is on a detached HEAD at an old commit (`f5dd80a`). `git pull` does nothing on a detached HEAD because there's no branch to pull into. To fix it, run:

```sh
cd ~/projects/toolkit
git switch master
git pull
```

**What happens**

Current state:
  HEAD (detached)
    ↓
  f5dd80a (old master tip)
    
  master (upstream)
    ↓
  34 commits ahead
    ↓
  (new CLI, lanes-board code)

After: git switch master && git pull
  HEAD (attached)
    ↓
  master
    ↓
  latest commit (new code)

**What's safe**

You have a 2-line edit in `prototypes/lanes-board.html` and an untracked `CONTEXT.md`. Both stay. The upstream changes only touched `src/` and `README.md`, so your files move with you to the new branch without conflict.

No `bun install` is needed. The merge added no dependencies. There's no build step, so the next time you run `bun src/sync.ts` (or `--watch`), it uses the new lanes-board code right away.

After the switch and pull, a sync pass against a live map gives you the first real `lanes #<n>` tab. If you type `! cd ~/projects/toolkit && git switch master && git pull` in the prompt, the update runs here and I can see the result.
