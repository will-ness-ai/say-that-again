**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions have different dangers, both settled upstream:

- **Open (→ public):** the channel grants `read_message_history` to all verified members. The full private history becomes readable at once. A later close does not retract it — people read it while it was open. #109 left "does the open path warn about this" to this ticket.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected the people who posted. Pure readers lose it with no signal. The ticket asks if the command names that number.

The bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. So both counts are cheap:

- Open: how many verified members gain access = verified count minus composite-role count.
- Close: how many lose access = the same number, for the same reason.

**Confirmation logic and its two cases**

```text
on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state
    report convergence
    return
  
  if visibility:public
    count = verified members − composite members
    prompt: "Full history readable by ~{count}. Later close won't undo. Continue?"
    on(Confirm) → grant read_message_history, report
    on(Cancel or 60s) → cancel
  
  if visibility:private
    count = verified members − composite members
    prompt: "{count} members lose access to #x. No notification. Continue?"
    on(Confirm) → revoke read_message_history, report
    on(Cancel or 60s) → cancel

on(/pillar-visibility channel:all visibility:public|private)
  collect all pillar channels
  if all already match declared state
    report convergence for each
    return
  
  count = sum of (verified − composite) across channels needing change
  prompt: "Batch affects {count} total members across {N} channels. Continue?"
  on(Confirm) → apply to all, report each
  on(Cancel or 60s) → cancel
```

A confirmation step protects against an argument slip. `visibility` is one choice field on one command — `public` and `private` sit one click apart.

The idempotent case must not nag. If the declared state already matches, there is no transition, so there is nothing to confirm. The command just converges and reports.

The "all channels" form (Q2) must confirm once for the batch, not once per channel. One confirmation covers all channels, with the channel list in the prompt. The buttons expire after 60 seconds. Expiry means cancel.

My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both. Do you agree?
