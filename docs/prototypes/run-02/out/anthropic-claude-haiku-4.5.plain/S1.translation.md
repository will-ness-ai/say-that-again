**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions have different dangers, both already decided upstream:

- **Open (→ public):** verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while it was open. Ticket #109 asked if the open path warns about this.
- **Close (→ private):** verified members without the composite role lose the channel at once. Auto-grant (#111) protected the people who posted. Pure readers lose it with no signal. The ticket asks if the command shows that number.

The code already has what we need. The bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are free:

- Open: verified members who gain access = verified count minus composite-role count.
- Close: verified members who lose access = the same number.

A confirmation step stops an argument slip. `visibility` is one choice field on one command — `public` and `private` sit one click apart. But the idempotent case must not nag. If the declared state already matches, there is no transition and nothing to confirm. The command just converges and reports. The "all channels" form (Q2) must confirm once for the batch, not once per channel.

My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.

| Case | Prompt | Action |
|------|--------|--------|
| Open | "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?" | On Confirm: set public, report. On Cancel or expire: return. |
| Close | "~N verified members lose access to #x. They get no notification. Continue?" | On Confirm: set private, report. On Cancel or expire: return. |
| State matches | (no prompt) | Report convergence. Repair drift if found. |
| Batch (all channels) | "Affects ~N members across M channels. Continue?" | On Confirm: apply to all, report each. On Cancel or expire: return. |

Buttons expire after 60 seconds. Expiry means cancel.
