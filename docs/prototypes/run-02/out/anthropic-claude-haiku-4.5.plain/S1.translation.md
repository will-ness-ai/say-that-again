**Q5 — Confirmation: which directions need confirmation, and what should they say?**

Step back. The two directions each have a risk, both already known:

- **Open (→ public):** the channel gives `read_message_history` to all verified members. The full private history becomes readable right away. A later close does not take it back — people read it while it was open. Ticket #109 asked if the open path should warn about this.
- **Close (→ private):** every verified member who does not have the composite role loses the channel right away. Auto-grant (#111) kept the people who posted. People who only read lose it with no message. The ticket asks if the command should name that number.

Facts from the code: the bot keeps all members in the gateway cache. `/pillar-list` already counts role holders from that cache. So both counts are fast:

- Open: how many verified members gain access = verified count minus composite-role count.
- Close: how many lose access = the same number, for the same reason.

```
┌─────────────────────────────────────────────────────────────┐
│ CONFIRMATION FLOW                                           │
└─────────────────────────────────────────────────────────────┘

OPEN (→ public)
├─ Condition: declared state differs from current
├─ Prompt: "This makes the full message history of #x 
│           readable by ~N verified members. 
│           A later close does not undo that. Continue?"
├─ Count: verified members − composite-role members
└─ Buttons: [Confirm] [Cancel] (expire 60s)

CLOSE (→ private)
├─ Condition: declared state differs from current
├─ Prompt: "~N verified members lose access to #x. 
│           They get no notification. Continue?"
├─ Count: verified members − composite-role members
└─ Buttons: [Confirm] [Cancel] (expire 60s)

NO CONFIRMATION
├─ Condition: declared state already matches current
└─ Action: report only, repair drift if found

BATCH FORM (all channels)
├─ Condition: declared state differs from current
├─ Prompt: one confirmation for all channels
│           (channel list included)
└─ Buttons: [Confirm] [Cancel] (expire 60s)
```

What this means:

- A confirmation step stops mistakes. `visibility` is one choice field on one command — `public` and `private` are one click apart.
- Do not ask again if the state already matches. If the declared state is already set, there is no change, so there is nothing to confirm. The command just reports the current state.
- The batch form (Q2) must ask once for all channels, not once per channel.

My recommendation: **confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- Do not confirm when the declared state already matches — the command only reports, and fixes drift if it finds any.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- The buttons expire after 60 seconds. Expiry means cancel.
