**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions carry different risks, both already decided upstream:

- **Open (→ public):** all verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while open. Ticket #109 asked whether the open path warns about this.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected people who posted. Pure readers lose it with no signal. The ticket asks if the command shows that number.

The code holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are cheap:

- Open: verified members who gain access = verified count minus composite-role count.
- Close: verified members who lose access = the same number.

A confirmation step stops an argument slip. `visibility` is one choice field on one command — `public` and `private` sit one click apart.

The idempotent case must not prompt. If the declared state already matches, there is no transition and nothing to confirm. The command converges and reports.

The "all channels" form (Q2) confirms once for the batch, not once per channel.

**My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- No confirmation when the declared state already matches — the command only reports and repairs drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- Buttons expire after 60 seconds. Expiry means cancel.

```text
on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state
    report convergence
    return
  
  if visibility:public
    count = verified members without composite role
    prompt "This makes full history readable by ~{count}. A later close does not undo that. Continue?"
    on(Confirm)
      grant read_message_history
      report success
    on(Cancel or 60s timeout)
      report cancelled
  
  if visibility:private
    count = verified members without composite role
    prompt "~{count} verified members lose access to #x. They get no notification. Continue?"
    on(Confirm)
      revoke read_message_history
      report success
    on(Cancel or 60s timeout)
      report cancelled

on(/pillar-visibility channel:all visibility:public|private)
  channels = all pillar channels
  count = sum of members affected across all channels
  prompt "Batch: {count} members affected across {len(channels)} channels. Continue?"
  on(Confirm)
    for each channel
      apply visibility change
      repair drift if found
    report batch complete
  on(Cancel or 60s timeout)
    report cancelled
```
