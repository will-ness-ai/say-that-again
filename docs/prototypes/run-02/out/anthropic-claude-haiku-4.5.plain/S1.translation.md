**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions carry different risks, both already decided:

- **Open (→ public):** all verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while open. Ticket #109 asked if the open path warns about this.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected people who posted. Pure readers lose it with no alert. The ticket asks if the command shows that number.

The code holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are free:

- Open: verified count minus composite-role count = how many gain access.
- Close: the same number = how many lose access.

A confirmation step stops an argument slip. `visibility` is one field on one command — `public` and `private` sit one click apart.

The idempotent case must not ask. If the declared state already matches, no transition happens, so nothing needs confirmation. The command converges and reports.

The "all channels" form (Q2) confirms once for the batch, not once per channel.

**My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- No confirmation when the declared state already matches — the command only reports and repairs drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- Buttons expire after 60 seconds. Expiry means cancel.

```text
on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state
    report convergence
    return
  
  count affected members from gateway cache
  show ephemeral confirmation prompt
    - Open: "~N verified members gain full history. Later close won't undo it."
    - Close: "~N members lose access. No notification sent."
    - buttons: [Confirm] [Cancel], expire 60s
  
  on(Confirm)
    apply state change
    repair any drift found
    report result
  
  on(Cancel or expiry)
    report cancelled

on(/pillar-visibility channel:all visibility:public|private)
  collect all pillar channels
  count total affected members across batch
  show one confirmation for entire batch
    - list channels
    - show total ~N
  on(Confirm)
    apply to each channel
    report per-channel results
```
