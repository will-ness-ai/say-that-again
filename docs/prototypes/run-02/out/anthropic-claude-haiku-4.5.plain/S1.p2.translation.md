**Q5 — Confirmation: which directions confirm, and what do they say?**

Zoom out. The two directions have different risks, both handled before this point:

- **Open (→ public):** the channel gives `read_message_history` to all verified members. The full private history becomes readable right away. A later close does not take it back — people read it while it was open. #109 asked "does the open path warn about this" and left it for this ticket.
- **Close (→ private):** every verified member without the composite role loses the channel right away. Auto-grant (#111) kept the people who posted. Pure readers lose it with no message. The ticket asks if the command names that number.

Facts from the code: the bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. So both counts are fast:

- Open: how many verified members gain access = verified count minus composite-role count.
- Close: how many lose access = the same number, for the same reason.

Implications:

- A confirmation step stops a slip of the hand. `visibility` is one choice field on one command — `public` and `private` sit one click apart.
- The case where nothing changes must not ask. If the declared state already matches, there is no change, so there is nothing to confirm. The command just moves to the target state and reports.
- The "all channels" form (Q2) must confirm once for the batch, not once per channel.

My recommendation: **confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

```
┌─────────────────────────────────────────────────────────────┐
│ CONFIRMATION FLOW                                           │
└─────────────────────────────────────────────────────────────┘

OPEN (→ public)
├─ Condition: declared state ≠ current state
├─ Count: verified members − composite-role members = N
├─ Prompt: "This makes the full message history of #x readable
│           by ~N verified members. A later close does not undo
│           that. Continue?"
└─ Buttons: [Confirm] [Cancel] (expire 60s)

CLOSE (→ private)
├─ Condition: declared state ≠ current state
├─ Count: verified members − composite-role members = N
├─ Prompt: "~N verified members lose access to #x.
│           They get no notification. Continue?"
└─ Buttons: [Confirm] [Cancel] (expire 60s)

IDEMPOTENT (declared state = current state)
├─ No confirmation
├─ Command reports only
└─ Repairs drift if found

BATCH FORM (all channels)
├─ One confirmation for entire batch
├─ Channel list in prompt
└─ Buttons: [Confirm] [Cancel] (expire 60s)
```

- No confirmation when the declared state already matches — the command only reports, and repairs drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- The buttons expire after 60 seconds. Expiry means cancel.
