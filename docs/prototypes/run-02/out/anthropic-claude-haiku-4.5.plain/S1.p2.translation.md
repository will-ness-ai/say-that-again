**Q5 — Confirmation: which directions confirm, and what do they say?**

The two directions have different dangers, both already decided:

- **Open (→ public):** all verified members gain `read_message_history`. The full private history becomes readable at once. A later close does not take it back — people read it while it was open. #109 asked if the open path warns about this.
- **Close (→ private):** every verified member without the composite role loses the channel at once. Auto-grant (#111) protected the people who posted. Pure readers lose it with no signal. The ticket asks if the command shows that number.

The bot holds all members in the gateway cache. `/pillar-list` already counts role holders from that cache. Both counts are cheap:

- Open: verified count minus composite-role count = how many verified members gain access.
- Close: the same number = how many lose access.

A confirmation step protects against a slip of the argument. `visibility` is one choice field on one command — `public` and `private` sit one click apart.

The idempotent case must not nag. If the declared state already matches, there is no transition, so there is nothing to confirm. The command just converges and reports.

The "all channels" form (Q2) must confirm once for the batch, not once per channel.

**Confirmation logic and its two cases**

```text
on(/pillar-visibility)
  if declared state matches current state
    report convergence
    return
  
  if direction is open (→ public)
    count = verified members − composite members
    prompt: "Makes history readable by ~{count}. A later close does not undo. Continue?"
    on(Confirm) → grant read_message_history, report
    on(Cancel or 60s) → return
  
  if direction is close (→ private)
    count = verified members − composite members
    prompt: "{count} members lose access. No notification sent. Continue?"
    on(Confirm) → revoke read_message_history, report
    on(Cancel or 60s) → return

on(/pillar-visibility channel:all ...)
  collect all pillar channels with state mismatch
  show one confirmation for the batch
  on(Confirm) → apply to all, report per-channel
```

My recommendation: confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- No confirmation when the declared state already matches — the command only reports, and repairs drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- The buttons expire after 60 seconds. Expiry means cancel.
