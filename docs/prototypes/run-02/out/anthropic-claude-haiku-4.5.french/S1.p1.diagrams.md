replaces: the confirmation logic and its two cases

```text
on(/pillar-visibility)
  if declared state matches current state
    report convergence
    return
  
  if direction is open (→ public)
    count = verified members − composite members
    prompt: "Makes history readable by ~{count}. Later close won't undo. Continue?"
    on(Confirm) → grant read_message_history, report
    on(Cancel or 60s) → dismiss
  
  if direction is close (→ private)
    count = verified members − composite members
    prompt: "~{count} members lose access. No notification sent. Continue?"
    on(Confirm) → revoke read_message_history, report
    on(Cancel or 60s) → dismiss

on(/pillar-visibility channel:all)
  collect all transitions (idempotent ones filtered out)
  if any transitions exist
    count total members affected across all channels
    prompt: "Affects ~{count} members across {N} channels. Continue?"
    on(Confirm) → apply all, report per-channel
    on(Cancel or 60s) → dismiss
```

supplements: why both directions need confirmation

```text
Open (→ public)
  ├─ Danger: read_message_history grant is permanent
  │  (later close does not retract what was already read)
  └─ Guard: show verified count, require explicit Confirm

Close (→ private)
  ├─ Danger: verified members lose access silently
  │  (no notification, pure readers vanish)
  └─ Guard: show affected count, require explicit Confirm

Idempotent case
  └─ No confirmation: state already matches, nothing to confirm
```
