**Q5 — Confirmation : quelles directions confirment, et que disent-elles ?**

Recule. Les deux directions ont des risques différents, tous deux réglés en amont :

- **Ouvrir (→ public) :** le canal donne `read_message_history` à tous les membres vérifiés. L'historique privé complet devient lisible d'un coup. Une fermeture ultérieure ne l'annule pas — les gens l'ont lu pendant qu'il était ouvert. #109 a laissé « le chemin ouvert avertit-il de cela » à ce ticket.
- **Fermer (→ private) :** chaque membre vérifié sans le rôle composite perd le canal d'un coup. L'octroi automatique (#111) a protégé les gens qui ont posté. Les lecteurs purs le perdent sans signal. Le ticket demande si la commande nomme ce nombre.

Faits du code : le bot tient tous les membres dans le cache de la passerelle. `/pillar-list` compte déjà les titulaires de rôles à partir de ce cache. Les deux nombres coûtent peu :

- Ouvrir : combien de membres vérifiés gagnent l'accès = nombre de vérifiés moins nombre de rôle composite.
- Fermer : combien le perdent = le même nombre, pour la même raison.

Conséquences :

- Une étape de confirmation protège contre un glissement d'argument. `visibility` est un champ de choix unique sur une commande — `public` et `private` sont à un clic l'un de l'autre.
- Le cas idempotent ne doit pas harceler. Si l'état déclaré correspond déjà, il n'y a pas de transition, donc rien à confirmer. La commande converge et rapporte.
- La forme « tous les canaux » (Q2) doit confirmer une fois pour le lot, pas une fois par canal.

Ma recommandation : **confirme les deux directions avec des boutons Confirmer/Annuler éphémères, et affiche le nombre dans les deux.**

- Ouvrir : « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés. Une fermeture ultérieure ne l'annule pas. Continuer ? »
- Fermer : « ~N membres vérifiés perdent l'accès à #x. Ils ne reçoivent pas de notification. Continuer ? »
- Pas de confirmation quand l'état déclaré correspond déjà — la commande rapporte seulement, et répare la dérive si elle en trouve.
- Une confirmation couvre tous les canaux dans la forme lot, avec la liste des canaux dans l'invite.
- Les boutons expirent après 60 secondes. L'expiration signifie annuler.

on(/pillar-visibility channel:#x visibility:public|private)
  if declared state matches current state

  if visibility:public

    on(Cancel or 60s expiry)
