**Q5 — Confirmation : quelles directions confirment, et que disent-elles ?**

Recule. Les deux directions ont des risques différents, tous réglés en amont :

- **Ouvrir (→ public) :** le canal accorde `read_message_history` à tous les membres vérifiés. L'historique privé complet devient lisible d'un coup. Une fermeture ultérieure ne l'annule pas — les gens l'ont lu pendant qu'il était ouvert. #109 a laissé « est-ce que le chemin ouvert avertit de cela » à ce ticket.
- **Fermer (→ private) :** chaque membre vérifié sans le rôle composite perd le canal d'un coup. L'octroi auto (#111) a protégé les gens qui ont posté. Les lecteurs purs le perdent sans signal. Le ticket demande si la commande nomme ce nombre.

Faits du code : le bot tient tous les membres dans le cache de la passerelle. `/pillar-list` compte déjà les détenteurs de rôle depuis ce cache. Donc les deux comptes coûtent peu :

- Ouvrir : combien de membres vérifiés gagnent l'accès = nombre vérifié moins nombre avec rôle composite.
- Fermer : combien perdent l'accès = le même nombre, pour la même raison.

Conséquences :

- Une étape de confirmation protège contre un glissement d'argument. `visibility` est un champ de choix sur une commande — `public` et `private` sont à un clic l'un de l'autre.
- Le cas idempotent ne doit pas harceler. Si l'état déclaré correspond déjà, il n'y a pas de transition, donc rien à confirmer. La commande converge juste et rapporte.
- La forme « tous les canaux » (Q2) doit confirmer une fois pour le lot, pas une fois par canal.

Ma recommandation : **confirme les deux directions avec des boutons Confirm/Cancel éphémères, et affiche le nombre dans les deux.**

- Ouvrir : « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés. Une fermeture ultérieure ne l'annule pas. Continuer ? »
- Fermer : « ~N membres vérifiés perdent l'accès à #x. Ils ne reçoivent pas de notification. Continuer ? »
- Pas de confirmation quand l'état déclaré correspond déjà — la commande rapporte seulement, et répare la dérive si elle en trouve.
- Une confirmation couvre tous les canaux dans la forme de lot, avec la liste des canaux dans l'invite.
- Les boutons expirent après 60 secondes. L'expiration signifie annuler.

```
Commande : /pillar-list visibility:public (ou private)

├─ Vérifier : l'état déclaré correspond-il à l'état actuel ?
│  ├─ OUI → Rapporter l'état actuel, réparer toute dérive, quitter
│  └─ NON → procéder à la confirmation
│
├─ Calculer les membres affectés
│  ├─ Ouvrir (→public) :  nombre_vérifié - nombre_rôle_composite = N gagnent l'accès
│  └─ Fermer (→private) : nombre_vérifié - nombre_rôle_composite = N perdent l'accès
│
├─ Afficher l'invite de confirmation éphémère avec le nombre
│  ├─ Ouvrir :  « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés.
│  │            Une fermeture ultérieure ne l'annule pas. Continuer ? »
│  │            [Confirmer] [Annuler] (expire 60s)
│  │
│  └─ Fermer : « ~N membres vérifiés perdent l'accès à #x.
│             Ils ne reçoivent pas de notification. Continuer ? »
│             [Confirmer] [Annuler] (expire 60s)
│
└─ Sur Confirmer → exécuter la transition
   Sur Annuler ou Expiration → abandonner, pas de changement
```

**Forme de lot (tous les canaux) :** une confirmation couvre tous les canaux, avec la liste des canaux dans l'invite.
