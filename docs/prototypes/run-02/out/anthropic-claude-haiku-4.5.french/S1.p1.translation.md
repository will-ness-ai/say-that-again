**Q5 — Confirmation : quelles directions confirment, et que disent-elles ?**

Recule. Les deux directions ont des risques différents, tous deux réglés en amont :

- **Ouvrir (→ public) :** le canal donne `read_message_history` à tous les membres vérifiés. L'historique privé complet devient lisible d'un coup. Une fermeture plus tard ne le retire pas — les gens l'ont lu pendant qu'il était ouvert. #109 a laissé « est-ce que le chemin ouvert avertit de cela » à ce ticket.
- **Fermer (→ private) :** chaque membre vérifié sans le rôle composite perd le canal d'un coup. L'octroi auto (#111) a protégé ceux qui ont posté. Les lecteurs purs le perdent sans signal. Le ticket demande si la commande nomme ce nombre.

Faits du code : le bot tient tous les membres dans le cache de la passerelle. `/pillar-list` compte déjà les titulaires de rôle à partir de ce cache. Les deux comptes coûtent peu :

- Ouvrir : combien de membres vérifiés gagnent l'accès = nombre vérifié moins nombre avec rôle composite.
- Fermer : combien le perdent = le même nombre, pour la même raison.

Conséquences :

- Une étape de confirmation protège contre un glissement d'argument. `visibility` est un seul champ de choix sur une seule commande — `public` et `private` sont à un clic l'un de l'autre.
- Le cas idempotent ne doit pas harceler. Si l'état déclaré correspond déjà, il n'y a pas de transition, donc rien à confirmer. La commande converge juste et rapporte.
- La forme « tous les canaux » (Q2) doit confirmer une fois pour le lot, pas une fois par canal.

Ma recommandation : **confirme les deux directions avec des boutons Confirmer/Annuler éphémères, et montre le nombre dans les deux.**

- Ouvrir : « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés. Une fermeture plus tard ne défait pas cela. Continuer ? »
- Fermer : « ~N membres vérifiés perdent l'accès à #x. Ils ne reçoivent pas de notification. Continuer ? »
- Pas de confirmation quand l'état déclaré correspond déjà — la commande rapporte seulement, et répare la dérive si elle en trouve.
- Une confirmation couvre tous les canaux dans la forme lot, avec la liste des canaux dans l'invite.
- Les boutons expirent après 60 secondes. L'expiration signifie annuler.

```
/pillar-visibility channel:#x visibility:public

  ↓ vérifie l'état actuel

  l'état correspond ?
  ├─ oui  → rapporte « déjà public » + répare toute dérive
  └─ non  → affiche la confirmation
           ├─ Ouvrir (→public) :  « ~N membres gagnent l'accès. L'historique reste lisible. Continuer ? »
           ├─ Fermer (→private) : « ~N membres perdent l'accès. Pas de notification. Continuer ? »
           └─ [Confirmer] [Annuler] (expire 60s)
              ├─ Confirmer → applique + rapporte
              └─ Annuler ou expire → rapporte « annulé »

/pillar-visibility channel:all visibility:public

  ↓ collecte tous les canaux pilier

  un état ne correspond pas ?
  ├─ non  → rapporte « tous déjà public »
  └─ oui  → affiche une confirmation pour le lot
           « Canaux : #a, #b, #c
            ~N membres gagnent l'accès partout. Continuer ? »
           └─ [Confirmer] [Annuler] (expire 60s)
```
