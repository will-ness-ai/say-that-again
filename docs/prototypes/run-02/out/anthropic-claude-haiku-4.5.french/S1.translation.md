**Q5 — Confirmation : quelles directions confirment, et que disent-elles ?**

Recule. Les deux directions ont des risques différents, tous deux réglés en amont :

- **Ouvrir (→ public) :** le canal donne `read_message_history` à tous les membres vérifiés. L'historique privé complet devient lisible d'un coup. Une fermeture plus tard ne le retire pas — les gens l'ont lu pendant qu'il était ouvert. Le ticket #109 a laissé « est-ce que le chemin ouvert avertit de cela » à ce ticket.
- **Fermer (→ private) :** chaque membre vérifié sans le rôle composite perd le canal d'un coup. L'octroi automatique (#111) a protégé les gens qui ont posté. Les lecteurs purs le perdent sans signal. Le ticket demande si la commande nomme ce nombre.

Faits du code : le bot tient tous les membres dans le cache de la passerelle. `/pillar-list` compte déjà les titulaires de rôle à partir de ce cache. Les deux comptes coûtent peu :

- Ouvrir : combien de membres vérifiés gagnent l'accès = nombre vérifié moins nombre de rôle composite.
- Fermer : combien perdent l'accès = le même nombre, pour la même raison.

Conséquences :

- Une étape de confirmation protège contre un glissement d'argument. `visibility` est un champ de choix sur une commande — `public` et `private` sont à un clic l'un de l'autre.
- Le cas idempotent ne doit pas harceler. Si l'état déclaré correspond déjà, il n'y a pas de transition, donc rien à confirmer. La commande converge juste et rapporte.
- La forme « tous les canaux » (Q2) doit confirmer une fois pour le lot, pas une fois par canal.

Ma recommandation : **confirme les deux directions avec des boutons Confirmer/Annuler éphémères, et montre le nombre dans les deux.**

- Ouvrir : « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés. Une fermeture plus tard ne défait pas cela. Continuer ? »
- Fermer : « ~N membres vérifiés perdent l'accès à #x. Ils ne reçoivent pas de notification. Continuer ? »
- Pas de confirmation quand l'état déclaré correspond déjà — la commande rapporte juste, et répare la dérive si elle en trouve.
- Une confirmation couvre tous les canaux dans la forme de lot, avec la liste des canaux dans l'invite.
- Les boutons expirent après 60 secondes. L'expiration signifie annuler.

```
/pillar-visibility channel:#x visibility:public
  ↓
état déjà public ?
  ├─ oui → rapporte « déjà public » (pas de confirmation)
  └─ non → affiche l'invite de confirmation
          « Cela rend l'historique complet des messages de #x lisible par ~N membres vérifiés.
           Une fermeture plus tard ne défait pas cela. Continuer ? »
          [Confirmer] [Annuler] (expire 60s)

/pillar-visibility channel:#x visibility:private
  ↓
état déjà private ?
  ├─ oui → rapporte « déjà private » (pas de confirmation)
  └─ non → affiche l'invite de confirmation
          « ~N membres vérifiés perdent l'accès à #x.
           Ils ne reçoivent pas de notification. Continuer ? »
          [Confirmer] [Annuler] (expire 60s)

/pillar-visibility channel:all visibility:public|private
  ↓
état correspond déjà sur tous ?
  ├─ oui → rapporte « tous déjà [public|private] » (pas de confirmation)

          « [liste des canaux]
           Cela affecte ~N membres vérifiés sur tous les canaux.
           [avertissement spécifique à la direction]
           Continuer ? »
          [Confirmer] [Annuler] (expire 60s)
```
