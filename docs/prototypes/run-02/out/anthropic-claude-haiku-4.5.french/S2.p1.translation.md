Votre checkout principal est bloqué sur une **HEAD détachée** à l'ancienne pointe de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Lancez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

Ce que cette opération touche :

- Vous avez une petite modification locale (2 lignes) dans `prototypes/lanes-board.html` et un fichier non suivi `CONTEXT.md`. Les deux sont sûrs : la fusion a changé seulement `src/` et `README.md`, donc le changement de branche et le pull les conservent sans conflit.
- Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de build, donc le prochain appel `bun src/sync.ts` (ou `--watch`) utilise le nouveau code lanes-board immédiatement.

```
HEAD détachée à f5dd80a (ancienne pointe de master)
  ↓ git switch master
  ↓ (conserve : modification de prototypes/lanes-board.html, CONTEXT.md)
branche master (suivi upstream)
  ↓ git pull
  ↓ (fusionne : changements de src/, README.md)
toolkit à jour
  ↓ bun src/sync.ts
  ↓ (utilise le nouveau code lanes-board immédiatement)
prêt à synchroniser
```

Après cela, une passe de sync sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans le prompt, la mise à jour s'exécute ici et je peux voir le résultat.
