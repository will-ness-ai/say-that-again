Votre checkout principal est sur une **HEAD détachée** à l'ancienne pointe de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Lancez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

**État actuel de votre checkout et ce qui doit se passer :**

```text
État actuel :
  HEAD (détachée)
    ↓
  f5dd80a (ancienne pointe de master)
  
  master (en amont)
    ↓
  f5dd80a + 34 commits en avant

Après : git switch master && git pull
  HEAD (sur master)
    ↓
  f5dd80a + 34 commits (nouvelle pointe de master)
```

**Fichiers affectés par le changement de branche et la fusion :**

```text
Vos modifications locales :
  prototypes/lanes-board.html    ✓ sûr (pas touché en amont)
  CONTEXT.md                     ✓ sûr (non suivi)

Modifications en amont :
  src/                           (fusionné)
  README.md                      (fusionné)
```

Remarques sur ce que cela touche :

- Vous avez une petite modification locale (2 lignes) dans `prototypes/lanes-board.html` et un `CONTEXT.md` non suivi. Les deux sont sûrs : la fusion a changé seulement `src/` et `README.md`, donc le changement de branche et le pull les conservent sans conflit.
- Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de build, donc le prochain appel à `bun src/sync.ts` (ou `--watch`) utilise immédiatement le nouveau code lanes-board.

Après cela, une passe de sync sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans l'invite, la mise à jour s'exécute ici et je peux voir le résultat.
