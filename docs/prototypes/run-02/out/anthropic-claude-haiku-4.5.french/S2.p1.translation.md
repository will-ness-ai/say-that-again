Votre extraction locale se trouve sur une **HEAD détachée** à l'ancienne pointe de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Exécutez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

Remarques sur ce que cela touche :

- Vous avez une petite modification locale (2 lignes) dans `prototypes/lanes-board.html` et un `CONTEXT.md` non suivi. Les deux sont sûrs : la fusion a modifié seulement `src/` et `README.md`, donc le changement de branche et le pull les conservent sans conflit.
- Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de compilation, donc le prochain appel `bun src/sync.ts` (ou `--watch`) utilise immédiatement le nouveau code lanes-board.

État actuel :
```
  HEAD (détachée)
    ↓
  f5dd80a (ancienne pointe de master)
  
  master (en amont)
    ↓
  34 commits en avant
    ↓
  (nouvelle CLI, code lanes-board)

Après `git switch master && git pull` :
  HEAD (sur master)
    ↓
  master (en amont)
    ↓
  dernier commit
```

Fichiers affectés :
```
prototypes/lanes-board.html    ← votre modification de 2 lignes (conservée sans risque)
src/                           ← mis à jour par la fusion
README.md                       ← mis à jour par la fusion
CONTEXT.md                      ← non suivi (inchangé)
```

Après cela, une passe de synchronisation sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans l'invite, la mise à jour s'exécute ici et je peux voir le résultat.
