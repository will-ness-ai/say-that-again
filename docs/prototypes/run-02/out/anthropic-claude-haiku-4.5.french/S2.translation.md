Votre checkout principal est sur une **HEAD détachée** à l'ancienne pointe de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Lancez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

État actuel :

```text
HEAD (détachée)
  ↓
  f5dd80a (ancienne pointe de master)
  
master (en amont)
  ↓
  (34 commits en avant)

Après : git switch master && git pull
HEAD (sur master)
  ↓
  (dernière pointe de master)
```

Fichiers locaux et en amont :

```text
Changements locaux :
  prototypes/lanes-board.html    ✓ sûr (pas de changement en amont)
  CONTEXT.md                     ✓ sûr (non suivi)

Changements en amont :
  src/                           (nouveau code lanes-board)
  README.md                      (mis à jour)
  
Résultat : le switch et le pull conservent vos modifications, pas de conflit
```

Vous avez une petite modification locale (2 lignes) dans `prototypes/lanes-board.html` et un `CONTEXT.md` non suivi. Les deux sont sûrs : la fusion a changé seulement `src/` et `README.md`, donc le switch et le pull les conservent sans conflit.

Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de build, donc le prochain appel `bun src/sync.ts` (ou `--watch`) utilise le nouveau code lanes-board immédiatement.

Après cela, une passe de sync sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans l'invite, la mise à jour s'exécute ici et je peux voir le résultat.
