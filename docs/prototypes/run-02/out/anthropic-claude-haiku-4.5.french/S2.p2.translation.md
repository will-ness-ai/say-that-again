Votre checkout principal est sur une **HEAD détachée** à l'ancienne pointe de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Exécutez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

État actuel :
  HEAD (détachée)
    ↓
  f5dd80a (ancienne pointe de master)
  
  master (en amont)
    ↓
  f5dd80a + 34 commits en avance

Après `git switch master && git pull` :
  HEAD (sur master)
    ↓
  f5dd80a + 34 commits (nouvelle pointe de master)

Remarques sur ce que cela touche :

Vous avez une petite modification locale (2 lignes) dans `prototypes/lanes-board.html` et un fichier non suivi `CONTEXT.md`. Les deux sont sûrs : la fusion a changé seulement `src/` et `README.md`, donc le changement de branche et le pull les conservent sans conflit.

Modifications locales (sûres à conserver) :
  prototypes/lanes-board.html    (modification de 2 lignes, pas de changement en amont)
  CONTEXT.md                      (non suivi, ignoré)

Modifications en amont (vont fusionner) :
  src/                            (nouvelles commandes, point d'entrée renommé)
  README.md                       (documentation mise à jour)

Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de compilation, donc le prochain appel `bun src/sync.ts` (ou `--watch`) utilise immédiatement le nouveau code lanes-board.

Après cela, une passe de synchronisation sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans l'invite, la mise à jour s'exécute ici et je peux voir le résultat.
