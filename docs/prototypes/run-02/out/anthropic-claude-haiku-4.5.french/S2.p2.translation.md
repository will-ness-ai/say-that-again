Votre checkout principal est sur une **HEAD détachée** à l'ancien sommet de master (`f5dd80a`), donc un simple `git pull` ne fonctionnera pas. Lancez :

```sh
cd ~/projects/toolkit
git switch master
git pull
```

État actuel et après la mise à jour :

```text
État actuel :
  HEAD (détachée)
    └─ f5dd80a (ancien sommet de master)
         └─ 34 commits en retard
              └─ master (upstream actuel)

Après : git switch master && git pull
  HEAD (sur master)
    └─ dernier commit (inclut les nouvelles commandes)

Fichiers affectés :
  ✓ prototypes/lanes-board.html    (votre édition de 2 lignes passe sans risque)
  ✓ CONTEXT.md                      (non suivi, inchangé)
  ✗ src/                            (mis à jour par la fusion)
  ✗ README.md                       (mis à jour par la fusion)
```

Vous avez une petite édition locale (2 lignes) dans `prototypes/lanes-board.html` et un `CONTEXT.md` non suivi. Les deux sont sûrs : la fusion a changé seulement `src/` et `README.md`, donc le changement de branche et le pull les conservent sans conflit.

Aucun `bun install` n'est nécessaire — la fusion n'a ajouté aucune dépendance. Il n'y a pas d'étape de compilation, donc le prochain appel de `bun src/sync.ts` (ou `--watch`) utilise immédiatement le nouveau code lanes-board.

Après cela, une passe de synchronisation sur une carte en direct vous donne le premier vrai onglet `lanes #<n>`. Si vous tapez `! cd ~/projects/toolkit && git switch master && git pull` dans l'invite, la mise à jour s'exécute ici et je peux voir le résultat.
