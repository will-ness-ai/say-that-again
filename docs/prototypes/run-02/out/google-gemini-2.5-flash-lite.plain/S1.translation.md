**Q5 — Confirmation: Which directions confirm, and what do they say?**

Zoom out. The two directions have different risks. Both risks were settled earlier:

- **Open (→ public):** The channel gives `read_message_history` to all verified members. The full private history becomes readable at once. Closing it later does not take back the history. People read it while it was open. Ticket #109 left the question "Does the open path warn about this?" to this ticket.
- **Close (→ private):** Every verified member without the composite role loses access to the channel at once. Auto-grant (#111) protected people who posted. Pure readers lose access with no warning. The ticket asks if the command names warn about this.

Facts from the code: The bot keeps all members in the gateway cache. `/pillar-list` already counts role holders from that cache. So both counts are cheap:

- Open: The number of verified members who gain access equals the verified count minus the composite-role count.
- Close: The number who lose access equals the same number, for the same reason.

Implications:

- A confirmation step protects against an argument slip. `visibility` is one choice field on one command. `public` and `private` are one click apart.
- The case where the state is already correct must not prompt. If the stated state already matches, there is no change. So there is nothing to confirm. The command just becomes correct and reports.
- The "all channels" form (Q2) must confirm once for the batch, not once per channel.

My recommendation: **Confirm both directions with ephemeral Confirm/Cancel buttons, and show the number in both.**

- Open: "This makes the full message history of #x readable by ~N verified members. A later close does not undo that. Continue?"
- Close: "~N verified members lose access to #x. They get no notification. Continue?"
- No confirmation when the stated state already matches — the command only reports, and fixes drift if it finds some.
- One confirmation covers all channels in the batch form, with the channel list in the prompt.
- The buttons expire after 60 seconds. Expiry means cancel.

function confirm_visibility_change(channel, new_visibility):
  current_visibility = get_channel_visibility(channel)

  if current_visibility == new_visibility:
    report("Channel #x already is " + new_visibility)
    return

  verified_count = count_verified_members()
  composite_role_count = count_members_with_composite_role()
  members_affected = verified_count - composite_role_count

  if new_visibility == "public":
    prompt = "This makes the full message history of #x readable by ~" + members_affected + " verified members. A later close does not undo that. Continue?"
  else: # new_visibility == "private"
    prompt = "~" + members_affected + " verified members lose access to #x. They get no notification. Continue?"

  show_confirmation_buttons(prompt, channel, new_visibility)

function handle_confirmation_response(channel, new_visibility, user_response):
  if user_response == "Confirm":
    apply_visibility_change(channel, new_visibility)
    report("Channel #x is now " + new_visibility)
  else: # Cancel or expired
    report("Operation cancelled for channel #x")

function confirm_batch_visibility_change(channels, new_visibility):
  affected_channels = []
  for channel in channels:
    current_visibility = get_channel_visibility(channel)
    if current_visibility != new_visibility:
      affected_channels.append(channel)

  if not affected_channels:
    report("All channels already are " + new_visibility)
    return

  # For simplicity, assume the number of affected members is the same for all channels in the batch
  # In a real implementation, this might need to be calculated per channel or aggregated.
  verified_count = count_verified_members()
  composite_role_count = count_members_with_composite_role()
  members_affected = verified_count - composite_role_count

  channel_list_string = join(affected_channels, ", ")

  if new_visibility == "public":
    prompt = "This makes the full message history of " + channel_list_string + " readable by ~" + members_affected + " verified members. A later close does not undo that. Continue?"
  else: # new_visibility == "private"
    prompt = "~" + members_affected + " verified members lose access to " + channel_list_string + ". They get no notification. Continue?"

  show_confirmation_buttons(prompt, affected_channels, new_visibility)

function handle_batch_confirmation_response(channels, new_visibility, user_response):
  if user_response == "Confirm":
    for channel in channels:
      apply_visibility_change(channel, new_visibility)
    report("Channels " + join(channels, ", ") + " are now " + new_visibility)
  else: # Cancel or expired
    report("Operation cancelled for channels " + join(channels, ", "))
