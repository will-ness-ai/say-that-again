**Q5 — Confirmation: which directions need it, and what does the prompt say?**

Step back. The two directions carry different dangers. Both were settled in earlier tickets:

- **Open (→ public):** the channel gives `read_message_history` to all verified members. The whole private history becomes readable straight away. Closing it later does not take that back — people read it while it was open. #109 left the question "does the open path warn about this?" to this ticket.
- **Close (→ private):** every verified member who does not hold the composite role loses the channel straight away. Auto-grant (#111) keeps the people who posted. People who only read lose it with no signal. This ticket asks whether the command tells you that number.

What the code gives us: the bot keeps all members in the gateway cache. `/pillar-list` already counts role holders from that cache. So both counts are cheap:

- Open: verified members who gain access = verified count minus composite-role count.
- Close: members who lose access = the same number, for the same reason.

What this means:

- A confirmation step guards against a slip in the arguments. `visibility` is one choice field on one command — `public` and `private` are one click apart.
- The no-change case must not nag. If the channel is already in the declared state, nothing changes, so there is nothing to confirm. The command simply converges and reports.
- The "all channels" form (Q2) must confirm once for the whole batch, not once per channel.

My recommendation: **confirm in both directions, with ephemeral Confirm/Cancel buttons, and show the number in both.**

```
N = verified_members - composite_role_holders     # both counts read from the gateway cache

on command(channels, visibility):
    changing = [c in channels where c.state != visibility]

    if changing is empty:                         # declared state already matches
        report state
        repair drift if found
        return                                    # nothing to confirm

    if visibility == public:
        text = "This makes the full message history of #x readable by
                ~N verified members. A later close does not undo that. Continue?"
    else:
        text = "~N verified members lose access to #x.
                They get no notification. Continue?"

    show ephemeral prompt(text, list of `changing`) + [Confirm] [Cancel]
                                                  # one prompt for the whole batch

    wait 60s:
        Confirm -> apply
        Cancel  -> stop
        expiry  -> stop                           # expiry means cancel
```
